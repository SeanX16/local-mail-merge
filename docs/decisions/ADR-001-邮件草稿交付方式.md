# ADR-001：邮件草稿交付方式

- 状态：Accepted
- 日期：2026-07-22
- 决策范围：公司电脑上的个性化邮件落地方式

## 背景

个性化邮件内容需要在外部电脑上由 Agent 生成，公司电脑不能依赖 AI，但必须使用公司的
Outlook 邮箱完成最终发送。项目比较了 `.eml`、Outlook 本地自动化和 Microsoft Graph。

## 实测证据

| 方案 | 公司电脑结果 |
|---|---|
| `.eml` | 可打开、可编辑，但关闭后不进入草稿箱 |
| Outlook 本地自动化 | 可编辑并可保存到草稿箱 |
| Microsoft Graph | Graph Explorer 无法登录公司邮箱 |

## 决策

1. 正式方案采用经典 Outlook 本地自动化创建草稿；
2. 批量创建只使用 `Save()`，不使用 `Display()` 和 `Send()`；
3. `.eml` 保留为单封邮件或无工具环境下的应急交付方式；
4. Microsoft Graph 暂停，不作为当前实现依赖；
5. 外部 Agent 与内部工具通过版本化 JSON 和审核 Excel 交接；
6. 最终发送必须由员工在 Outlook 中人工执行。

## 后果

### 正面

- 已在目标公司环境验证核心能力；
- 不需要公司邮箱登录凭据离开公司电脑；
- 不需要 Graph 应用注册和管理员授权；
- 可以批量保存真正的 Outlook 草稿；
- 可以在工具中实现预览、去重和本地审计。

### 代价

- 正式工具依赖 Windows 和经典 Outlook；
- 需要处理 Outlook 账户选择、签名、COM 异常和公司安全策略；
- 未来迁移到新版 Outlook 时可能需要更换适配器；
- 正式分发不宜长期依赖未签名 PowerShell 脚本。

## 重新评估条件

出现以下任一情况时重新评估 Graph 或其他适配器：

- 公司 IT 明确允许 Microsoft 365 应用注册和 `Mail.ReadWrite` 委托权限；
- 公司迁移到新版 Outlook，旧版本地自动化不可用；
- 需要共享邮箱、多设备同步或集中式草稿管理；
- 公司制定新的邮件发送、留档或合规要求。
