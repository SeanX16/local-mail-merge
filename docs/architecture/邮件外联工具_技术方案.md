# 邮件外联工具技术方案

状态：方案已选定，尚未进入正式工具实现
更新时间：2026-08-14

## 1. 方案结论

邮件外联工具采用“两段式、草稿优先”的架构：

```text
外部 Agent
  → 生成有来源的个性化邮件交接包
  → HR 审核并批准
  → 安全传入公司电脑
  → 本地无 AI 工具调用经典 Outlook
  → 批量 Save 到草稿箱
  → 员工逐封检查并点击发送
```

正式路线是 Outlook 本地自动化。`.eml` 作为应急备份；Microsoft Graph 在当前公司环境中暂缓。

## 2. 选型依据

### 2.1 Outlook 本地自动化

公司电脑实测可以创建可编辑邮件并保存到草稿箱，满足核心目标。正式批量处理只调用
`Save()`，不调用 `Display()` 或 `Send()`，因此不会为每位候选人弹出一个邮件窗口。

测试脚本中的 `Display()` 只用于人工观察兼容性，不属于正式批量流程。

### 2.2 `.eml`

公司环境可以打开并编辑 `.eml`，但关闭后不会保存到草稿箱。它仍可作为单封邮件的离线备用，
但不承担批量状态管理、去重和草稿落库。

### 2.3 Microsoft Graph

公司邮箱无法登录 Graph Explorer，因此当前无法完成公司账户授权和草稿创建。正式版本不依赖
Graph，也不为尚未开放的权限增加代码复杂度。

## 3. 组件边界

```text
Outreach Package Builder（外部，可使用 Agent）
  ├─ 读取已确认的人才数据和来源
  ├─ 生成个性化主题与正文
  ├─ 输出审核 Excel
  └─ 输出稳定 JSON

Outlook Draft Importer（内部，不使用 AI）
  ├─ Package Reader
  ├─ Validation Gate
  ├─ Review UI
  ├─ Duplicate Guard
  ├─ Outlook Draft Writer
  └─ Local Audit Report
```

两个部分只通过版本化交接包通信。内部工具不得读取外部 Agent 的运行缓存，也不得把公司邮箱
凭据交给外部工具。

## 4. 建议的数据合同

```json
{
  "schema_version": "outreach-package/v1",
  "batch_id": "siggraph_2022_outreach_001",
  "created_at": "2026-07-22T12:00:00+08:00",
  "messages": [
    {
      "person_id": "siggraph_2022_example_person",
      "recipient_name": "Example Person",
      "recipient_email": "example@university.test",
      "subject": "Research opportunity related to your graphics work",
      "body_html": "<p>...</p>",
      "target_role": "Graphics & Spatial Research Engineer",
      "personalization_facts": [
        {
          "text": "Published a relevant SIGGRAPH paper",
          "source_url": "https://example.test/source"
        }
      ],
      "review_status": "Approved",
      "content_hash": "sha256:..."
    }
  ]
}
```

`personalization_facts`、`review_status` 和 `content_hash` 是标准交接包的可选增强字段，不是通用
Excel、CSV 或 JSON 导入的必要条件。缺少 `content_hash` 不产生警告；如果交接包主动提供它，本地规则
可以选择是否检查收件邮箱、主题和正文在审核后发生变化。

本地工具始终根据实际收件邮箱、主题和正文计算内部内容哈希，用于草稿创建记录和重复保护，不依赖上游必须
提供 `content_hash`。

## 5. Outlook 草稿写入策略

### 5.1 批量行为

每封邮件执行：

```text
创建 MailItem
  → 指定发件账户
  → 设置 To / Subject / Body
  → 附加或保留公司签名
  → Save
  → 记录结果
  → 释放当前对象
```

批量流程不调用 `Display()`。全部完成后，工具只显示汇总，并可以提供一个“打开 Outlook”按钮。

### 5.2 发件账户

工具启动后必须显示可用 Outlook 账户，让用户明确选择本批次的发件账户。不能静默使用第一个
账户，也不能只根据邮箱字符串猜测账户。

### 5.3 公司签名

直接设置 `HTMLBody` 可能覆盖 Outlook 自动签名。正式实现优先支持以下一种受控方式：

1. 使用公司批准的 `.oft` 模板作为邮件基础；或
2. 由本地工具加载公司批准的签名 HTML，并插入个性化正文。

不得为了触发签名而在批量过程中逐封调用 `Display()`。

### 5.4 去重

本地工具至少保存：

- `batch_id`
- `person_id`
- 本地计算的邮件内容哈希
- Outlook `EntryID`
- 创建时间
- 创建结果

同一组 `batch_id + person_id + 本地计算的邮件内容哈希` 已成功时，默认拦截。用户可以在本地规则设置中
把“重复创建”调整为警告或默认放行。

校验规则采用版本化本地配置。邮箱无效固定拦截；重复创建默认拦截；主题为空、正文为空、占位符残留和邮箱
重复默认警告；尚未批准、没有个性化事实和审核后内容发生变化默认放行。创建草稿前重新读取交接包，并使用
当前规则再次校验。

## 6. 本地界面

首版建议使用小型 Windows 桌面程序，而不是要求 HR 直接运行 PowerShell：

```text
[选择 outreach_package.json]
[选择 Outlook 发件账户]
[选择公司签名或模板]

总数 20｜可创建 18｜需复核 2｜重复 0

☑ Example Person  example@university.test  Approved
☐ Review Person   Unknown                  Blocked

[预览] [创建所选草稿]
```

PowerShell 仅保留为技术验证工具。正式程序应由公司允许的签名和分发方式交付，避免依赖用户修改
PowerShell 执行策略。

## 7. 异常处理

- 某一封失败不得中断整个批次；
- 每个失败必须对应到 `person_id` 和可读错误；
- Outlook 未安装、无法启动或没有账户时，不创建任何草稿；
- 发件账户不明确时停止整个批次；
- 签名或模板不可用时，在创建前提示，不静默发送无签名版本；
- 本地日志不得包含 OAuth token、邮箱密码或其他登录凭据；
- 工具不得包含自动发送接口。

## 8. 实施阶段

### 阶段 A：三人离线 MVP

- 使用虚构或内部测试邮箱；
- 读取固定的 `outreach-package/v1`；
- 选择发件账户；
- 创建三封不弹窗草稿；
- 验证签名、格式、重启持久性和去重。

### 阶段 B：小型 HR 审核界面

- Excel/JSON 一致性检查；
- 批量选择与逐封预览；
- 错误汇总和本地操作记录。

### 阶段 C：与顶会 Skill 交接

- 外部 Skill 输出符合合同的邮件交接包；
- 固化来源、人工批准和批次命名；
- 使用真实候选人前完成隐私和误操作验收。

每个阶段完成后单独验收，不在首版加入自动发送、追踪或 Graph。
