# 邮件外联工具｜明确需求整理

状态：已确认
确认日期：2026-07-22
最近调整：2026-08-14（校验规则改为本地可配置）

## 1. 与原始需求的关系

本文件记录项目启动后新增的邮件外联需求，不覆盖或改写：

- `info.md`
- `HR_AI人才信息工具_明确需求整理.md`

原始文件仍是顶会人才工具和简历处理工具的需求依据。本文件是邮件外联工具的当前实现口径。

## 2. 项目优先级

1. 使用外部 Agent Skill 抓取并整理顶会人才名单；
2. 在公司电脑上将个性化邮件批量创建为 Outlook 草稿；
3. 最后开发完全本地的简历处理工具。

## 3. 目标

外部电脑可以使用 Agent，根据每位候选人的公开且有来源的信息生成不同的邮件主题和正文。
公司内部电脑不使用 AI，只读取已经审核的交接包，将收件人、主题和正文自动组合成可编辑的
Outlook 草稿。员工逐封检查后，在 Outlook 中手动点击发送。

## 4. 系统边界

### 4.1 外部电脑

- 可以使用 Agent 生成个性化邮件内容；
- 个性化描述必须来自已记录来源，不得凭空补充经历、能力或身份属性；
- 输出供人审核的 Excel 和供本地工具读取的结构化 JSON；
- 不持有公司邮箱登录凭据；
- 不连接公司 Outlook，也不发送邮件。

### 4.2 公司内部电脑

- 不调用大模型或外部内容生成服务；
- 使用员工当前已登录的经典 Outlook；
- 只创建和保存草稿，不调用自动发送；
- 邮件地址、正文、草稿标识和操作日志只保存在公司批准的位置；
- 运行所需脚本或程序必须符合公司 IT 安全策略。

## 5. 外部交接包

通用 Excel、CSV 或 JSON 导入至少需要能够识别收件邮箱。主题和正文缺失时仍可导入，并由本地规则决定
是否警告或拦截。缺少 `person_id` 时，本地工具可以为当前行生成内部标识。

标准 `outreach-package/v1` 可以额外包含：

- `batch_id`
- `person_id`
- `recipient_name`
- `recipient_email`
- `subject`
- `body_text` 或 `body_html`
- `target_role`
- `personalization_facts`
- `generated_at`
- `review_status`
- `content_hash`

推荐同时交付：

- `Outreach_Review.xlsx`：供 HR 审核、筛选和批准；
- `outreach_package.json`：供本地工具稳定读取。

这些增强字段不是通用 Excel、CSV 导入的前置条件。人工批准、个性化事实和内容哈希是否参与校验，由公司
电脑上的本地规则配置决定。

## 6. 本地工具功能

### 6.1 必须实现

- 选择并导入邮件交接包；
- 按本地规则配置校验邮箱、主题、正文、审核状态和重复情况；
- 显示收件人列表和逐封邮件预览；
- 允许人工勾选本次创建草稿的人员；
- 通过 Outlook 本地自动化创建并保存草稿；
- 批量运行时不逐封打开 Outlook 撰写窗口；
- 支持选择正确的发件账户；
- 支持公司批准的邮件签名；
- 防止同一批次、同一人员、同一内容重复创建草稿；
- 输出成功、跳过、失败和需要复核的本地报告。

### 6.2 可配置分级校验（2026-08-14 调整）

由于本工具只保存草稿、不自动发送，用户可以在设置页把可配置规则拖到“拦截”“警告”或“默认放行”。
规则保存在当前 Windows 用户的本地应用目录中，导入和创建草稿前使用同一份配置。
同一分级内的规则也可以拖动排序；该顺序同时决定主页面邮件预览中校验提示的排列顺序。

固定系统保护：

- 邮箱无效、缺失或仍为 `Unknown`；
- 同一批次存在重复 `person_id` 时，由程序作为数据完整性问题固定拦截，不作为可移动的内容规则；
- 创建前重新读取交接包并重新校验；
- 正式批量流程只调用 Outlook `Save()`，不存在自动发送路径。

默认放在“拦截”的可移动规则：

- 相同批次、人员和实际邮件内容已经成功创建过草稿。
- 主题为空；
- 正文为空。

默认放在“警告”的可移动规则：

- 主题或正文仍含 `{FirstName}` 等未替换占位符；
- 同一批次存在重复邮箱。

默认放行、但可以拖到警告或拦截的规则：

- `review_status` 未批准或缺失；
- 没有个性化事实；
- 交接包已提供 `content_hash`，但邮箱、主题或正文与其不一致。

缺少 `content_hash` 或 `source_url` 本身不产生问题。`do_not_contact` 不再属于本工具的校验规则。

警告记录默认不自动勾选。用户主动选择后，创建确认框必须汇总警告；最终仍由员工在 Outlook 中逐封检查并
手动发送。

### 6.3 当前不实现

- 程序自动发送邮件；
- 自动批量发送；
- 自动跟进或自动回复；
- 打开率、点击率等追踪；
- 在公司电脑上调用 AI；
- CRM 或完整招聘管理系统。

## 7. 已验证的公司环境结果

2026-07-22 在公司电脑完成三条路线的兼容性测试：

| 路线 | 实测结果 | 结论 |
|---|---|---|
| `.eml` 文件 | 可以打开和编辑，但关闭后不会保存到草稿箱 | 仅作为应急交付方式 |
| Outlook 本地自动化 | 可以编辑，也可以保存到草稿箱 | 选为正式实现路线 |
| Microsoft Graph | Graph Explorer 无法登录公司邮箱 | 当前环境暂停开发 |

Graph 的结果表示当前公司环境中不可操作，不等同于从技术上永久否定。只有公司 IT 以后明确
开放公司账户登录和邮件 API 权限时，才重新评估。

## 8. 验收标准

首个可用版本至少应通过以下验收：

1. 使用虚构或内部测试数据一次创建多封相互独立的草稿；
2. 不打开大量 Outlook 邮件窗口；
3. 草稿进入指定公司邮箱的 Drafts 文件夹；
4. 收件人、主题、中文、英文、换行、链接和简单格式正确；
5. 公司签名正确且没有被正文覆盖；
6. Outlook 重启后草稿仍然存在；
7. 重复导入同一批次不会重复创建；
8. 工具代码中不存在自动发送路径；
9. 错误记录可以定位到具体 `person_id`；
10. 不提交邮件地址、正文、登录信息或运行日志到 Git。
