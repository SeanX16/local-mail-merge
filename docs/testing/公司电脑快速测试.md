# Local Mail Merge 公司电脑快速测试

本流程用于在公司 Windows 电脑上测试 GitHub Releases 中的免安装版。
测试时不调用 AI，不自动发送邮件，只向经典 Outlook 保存可人工检查的草稿。

## 1. 需要的环境

- Windows 10/11 x64；
- 经典 Outlook（不是“新 Outlook”），已登录测试账户；
- 公司策略允许运行该未签名内部测试程序；
- 可访问私有 GitHub 仓库的账户。

免安装 ZIP 已包含 Electron 和自包含 .NET Worker，公司电脑不需安装 Node.js、npm 或 .NET SDK。

## 2. 下载和解压

1. 打开私有仓库的 **Releases**，进入最新的 pre-release。
2. 下载 `Local-Mail-Merge-*-win-x64.zip` 和对应的 `.sha256.txt`。
3. 可选地用 Windows 自带命令核对文件：

   ```text
   certutil -hashfile Local-Mail-Merge-*-win-x64.zip SHA256
   ```

   输出应与 `.sha256.txt` 中的值一致。
4. 将 ZIP 完整解压到一个普通本地目录，例如 `Downloads\LocalMailMerge-Test`。
5. 不要在 ZIP 内直接运行，不要只复制 `LocalMailMerge.exe`；`resources` 和其他 DLL 都是运行必需文件。

如果 Defender、SmartScreen 或公司应用白名单拦截，不要关闭安全软件或绕过公司策略。
记录版本号和 SHA-256，向 IT 申请允许该内部测试包。

## 3. 五分钟安全验收

### A. 启动和账户

1. 先启动经典 Outlook，确认目标账户已正常登录。
2. 双击 `LocalMailMerge.exe`。
3. 确认界面尺寸正常，没有明显裁切或重叠。
4. 查看顶部 **Outlook 账户**，或进入 **设置 → Outlook 账户 → 重新检测**。
5. 确认程序显示的是准备用于测试的账户。

### B. 虚构数据导入

1. 点击 **导入交接包**。
2. 选择解压目录内的 `resources\samples\outreach_package.sample.json`。
3. 确认所有收件地址均为 `.test` 虚构域名，不是真实收件人。
4. 点击不同人员行，核对右侧收件人、主题、正文和校验提示会随行切换。
5. 检查“有警告”记录可人工勾选，“硬拦截”记录不可勾选。

### C. 签名预览和无收件人测试草稿

1. 在 **设置 → 邮件签名** 导入公司批准的 `.oft`、`.html` 或 `.htm`。
2. 核对检查结果；危险 HTML 或普通附件应被拦截，远程图片和有限预览应明确提示。
3. 确认设置页和主界面显示的是所选签名的实际内容；APP 内不应加载远程或本地图片。
4. 选择正确的真实 Outlook 账户，点击 **创建无收件人测试草稿**。
5. 在 Outlook 草稿箱确认该草稿没有收件人，核对排版和内嵌图片后删除，不要发送。

### D. 只创建一封批量测试草稿

1. 取消其他勾选，只保留一条 `.test` 记录。
2. 确认顶部邮件签名和 Outlook 账户正确。
3. 点击 **创建所选草稿**，在确认框内再次核对数量为 1。
4. 创建完成后打开 Outlook 草稿箱，确认：
   - 只有一封新草稿；
   - 没有自动弹出大量撰写窗口；
   - 收件人、主题、正文和签名符合预览；
   - 草稿没有被发送。
5. 删除该 `.test` 测试草稿。
6. 重新导入同一示例，确认已成功创建的同批次、同人员和同内容被重复保护拦截。

## 4. 真实工作簿只读测试

在虚构数据通过后，可导入工作中的 Excel 做界面和校验测试，但首轮不创建草稿：

1. 选择人员数据所在 Sheet 和字段名所在行；
2. 确认导入人数、可创建、警告和硬拦截数量；
3. 测试字段管理、列筛选、行选择和邮件预览；
4. 关闭程序，核对原始 Excel 的修改时间和内容未变。

真实名单、邮箱、邮件正文、审计报告或未脱敏截图不得上传到 GitHub Issue。

## 5. 发现问题时记录

请记录：

- Release 版本和 ZIP SHA-256；
- Windows 版本、屏幕分辨率和缩放比例；
- Outlook 是经典版还是新版；
- 账户是否被检测；
- 使用虚构数据还是已脱敏数据；
- 可稳定复现的最少步骤和错误文案。

只提交脱敏截图和脱敏错误信息。如果日志或截图包含收件人、主题、正文或 Outlook 账户，先在公司电脑上脱敏。

## 6. 分发形态说明

- ZIP 本身免安装，删除解压目录即可移除程序文件；
- 设置与已导入签名保存在 `%APPDATA%\Local Mail Merge\`；
- 草稿去重审计和本地报告保存在 `%LOCALAPPDATA%\HKRC\LocalMailMerge\`；
- 如需完全清理测试状态，先确认不再需要已导入签名、去重记录和报告，再按公司 IT 规则删除上述两个目录。

## 7. 开发者备用流程

只有需要修改源码时才需要在公司电脑克隆仓库并构建：

```text
git clone <private-repository-url>
cd local-mail-merge\src\LocalMailMerge.Desktop
npm ci
npm run make
```

该路线需要 Node.js、npm、.NET SDK 和可访问 NuGet/npm 的网络，不是普通测试人员的推荐流程。
